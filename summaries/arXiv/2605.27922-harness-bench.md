# Harness-Bench: Measuring Harness Effects across Models in Realistic Agent Workflows

> Source: arXiv:2605.27922 (27 May 2026). Yao, Tan, Liu, Li, Wang, Yu, Tan, Tian, Zhao, Sun, Zhang, Yang (Peking University; Qiyuan Tech). PDF in `../../sources/arXiv/2605.27922-harness-bench.pdf`.

## Thesis
Agent performance depends not only on the base model but also on the "harness" — the system layer that manages context, tools, state, permissions, tracing, and recovery. Harness-Bench is a diagnostic benchmark that fixes the task, budget, timeout, sandbox, and evaluator while varying the harness across multiple model backends, so the execution layer becomes the primary axis of comparison. The authors argue agent capability should be reported at the model–harness configuration level, not attributed to the base model alone.

## Key findings
- Scale: 106 sandboxed offline tasks across 8 workflow categories, 6 configurable harnesses × 8 API model backends = 5,088 trajectories, plus Codex (model-bound coding agent) adding 106, for 5,194 total trajectories (Abstract; §4.1; Appendix B).
- Headline harness effect: holding the same task set and model-backend pool fixed, aggregate score ranges from NanoBot 76.2% (best configurable) down to OpenClaw 52.4% (worst) — a 23.8-point gap purely from the harness (Table 2; §4.2).
- The best harness differs from the raw completion leader story: NanoBot leads completion at 81.6% vs OpenClaw's 60.0%, and does so with fewer tokens (68.7K) than Hermes (139.7K), ZeroClaw (133.2K), NullClaw (175.1K), Moltis (134.9K) — longer trajectories do not buy performance (Table 2; §4.2).
- Efficiency varies wildly by harness: turns range from 5.0 (OpenClaw) to 22.6 (Hermes); tokens from 68.7K (NanoBot) to 175.1K (NullClaw) (Table 2).
- Model effect vs harness effect: stronger model backends achieve higher mean scores AND lower cross-harness variance; weaker backends are far more sensitive to the harness. Per-model average scores cluster in a ~0.575–0.71 mean band (Figure 3), i.e., the harness swing (52.4→76.2) is comparable in magnitude to the model swing — stronger models are more "harness-tolerant."
- Harness dependence is category-specific: cross-harness variance is highest in Data/BI/Finance Analytics (0.0155), Workspace/Tool Use (0.0130), and Software Engineering (0.0102); lowest in Office & Business Communication (0.0020) — harness matters most where success needs structured data manipulation, tool sequencing, and state tracking, not pure language generation (Figure 4; Appendix C).
- Failure modes among failed trajectories: Contract/format violations 36.4%, Tool/recovery failures 24.6%, Evidence/grounding 14.6%, Artifact commitment 11.1%, State/continuation 9.3% — framed as "execution drift," where plausible reasoning decouples from machine-checkable output, tool feedback, or workspace state (Table 3; §5).
- Codex (model-bound, GPT-5.4) scores 80.4% — competitive and above most GPT-backed configurable harnesses, but still slightly below NanoBot+GPT, and reported separately as a reference point rather than a controlled harness (Table 2; Figure 3; §4.2–4.3). Scoring is multiplicative: TaskScore = Security × Completion × Process (§3.4); claude-sonnet-4.6 is the fixed LLM judge (§4.1).

## Relevance to the book
This is the empirical anchor for expanding Chapter 4 §4.2.1 "Harness Engineering" under Agent Disciplines. Where the book asserts the harness matters, Harness-Bench measures it: a systematic benchmark that isolates the harness's effect on task success by holding the model fixed (and vice versa), showing a 23.8-point same-model swing from harness choice alone. It makes the case that the harness is a first-class engineering variable — capability is a property of "model + harness," not the model alone — and its failure taxonomy (contract/format, recovery, grounding, artifact commitment, state continuation) gives readers concrete failure classes to engineer against.

## Stance
Supportive empirical evidence — a rigorous, controlled benchmark that quantifies the harness as a decisive, first-class engineering variable.
