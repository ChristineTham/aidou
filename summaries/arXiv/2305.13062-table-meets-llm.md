# Table Meets LLM: Can Large Language Models Understand Structured Table Data? A Benchmark and Empirical Study

> Source: arXiv:2305.13062 (submitted 22 May 2023; v5 dated 17 Jul 2024). Sui, Zhou, Zhou, Han, Zhang. Published in WSDM '24 (17th ACM International Conference on Web Search and Data Mining, Mérida, Mexico), DOI 10.1145/3616855.3635752. PDF in `../../sources/arXiv/2305.13062-table-meets-llm.pdf`.

## Thesis
LLMs can be fed tables only after the table is *serialized* into linear text, yet prior work chose serialization formats and prompt scaffolding ad hoc, with no consensus on what works. The paper introduces the SUC (Structural Understanding Capabilities) benchmark of seven tasks (table partition, size detection, merged-cell detection, cell lookup, reverse lookup, column retrieval, row retrieval) to compare input formats and prompt options on GPT-3.5 and GPT-4. Its headline findings: (1) the choice of serialization format materially changes accuracy, with markup languages (especially HTML) generally beating comma/pipe-separated text; and (2) LLMs have only *basic* structural understanding of tables, failing even trivial tasks like counting rows/columns, though a two-pass "self-augmented prompting" method recovers meaningful gains.

## Key findings
- **Formats tested.** Six serialization formats were compared: NL+Sep (natural language with a `|` separator, the common baseline), Markdown, JSON, XML, HTML, and XLSX. Markup languages (HTML, XML, Markdown) are contrasted against separator-delimited text and against structured storage formats (CSV/JSON) throughout (§3.1, §3.4, Figure 2).
- **HTML wins overall.** On the SUC benchmark HTML gave the best average structural understanding; using markup languages, specifically HTML, beat "NL+Sep" by a **6.76%** improvement. The best full configuration — HTML markup + format explanation + role prompting + original input order — reached **65.43%** average accuracy across the seven tasks (§5.2.1, Table 3).
- **Per-task format table (GPT-3.5 Acc, Table 2).** HTML led or tied on most tasks: Table Partition 96.67% (vs Markdown 92.33%, NL+Sep 93.00%), Cell Lookup 44.00%, Column Retrieval 63.33% (Markdown only 35.33%), and Size Detection **67.00% for HTML vs 40.67% for Markdown / 42.00% NL+Sep / 42.67% JSON** — a large gap. XML was strongest on Reverse Lookup (55.00%). Markdown and XML tied HTML (~42%) on Row Retrieval.
- **Why HTML/XML help.** The authors attribute HTML/XML strength to LLM pretraining: code tuning plus large amounts of web (HTML) data make the models "more familiar" with markup than with bespoke separators (§5.2.1).
- **Verbosity / token cost is a real trade-off but not quantified with a multiplier.** The paper frames CSV, JSON, XML, Markdown, HTML and XLSX as offering "different levels of information compression" (§3.1, §3.4) — CSV is terse (commas), XML/HTML are verbose nested tags. It notes LLMs are inefficient on long inputs (quadratic self-attention), that text-davinci-003 is capped at 4k tokens (footnote 2), and that they must *random-sample rows* and truncate when a table exceeds the token budget (§2.2). So the more verbose markup formats consume context that limits how many rows fit — but the paper does **not** publish an explicit "HTML = N× more tokens than CSV/Markdown" figure. Describe as qualitative.
- **Downstream tasks confirm HTML.** On five reasoning datasets (Table 5), HTML was best among the text formats: TabFact 71.33%, HybridQA 47.29%, SQA 71.31%, Feverous 75.20%, ToTTo BLEU-4 12.30% — beating Markdown (68.40 / 45.88 / 66.59 / 71.88 / 8.57) and JSON. GPT-4 with HTML jumped further (TabFact 78.40%, HybridQA 56.68%, Feverous 83.21%).
- **LLMs are weak at basic structure.** Even trivial size detection (count rows/columns) is poor — GPT-3.5 scored 40–67% depending on format. Performance also collapses without a 1-shot example: removing the single in-context example dropped overall accuracy ~30.38% (HTML), e.g. size detection −50.33% and merged-cell −38.67% (Table 3).
- **Self-augmentation gains.** The proposed two-pass "self-augmented prompting" (ask the LLM to first describe the table — e.g. self-generated "critical values and ranges identification" — then answer) beat plain 1-shot by ~3.26% overall, with reported per-dataset lifts: TabFact +2.31%, HybridQA +2.13%, SQA +2.72%, Feverous +0.84%, ToTTo +5.68% (abstract, Table 4).

## Relevance to the book
"AI-dō" argues that when you hand context to a model, plain text formats are the lingua franca — this paper is the empirical backbone for Chapter 2 §2.4 "Everything Becomes Markdown". Its unique contribution is a controlled benchmark that pits Markdown, HTML, CSV/JSON, XML and pipe-separated text against each other for the *same* tables, showing the format is not neutral: markup (HTML best, then XML) consistently beats separator text and JSON, largely because models saw so much web HTML in training. It also surfaces the counter-tension the chapter should acknowledge — the best-understood formats (HTML/XML) are the *most verbose*, so they burn context budget and force row truncation, which is exactly the practical reason Markdown (compact, still markup-like, well understood) is often the sweet spot for feeding tables to a model.

## Stance
Supportive, format-sensitive — empirical evidence that serialization format changes LLM comprehension, with a verbosity-vs-understanding trade-off (HTML best-understood but heaviest; Markdown a compact compromise).
