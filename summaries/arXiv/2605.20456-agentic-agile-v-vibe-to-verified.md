# Agentic Agile-V: From Vibe Coding to Verified Engineering in Software and Hardware Development

> Source: arXiv:2605.20456 (2026-05-19). Christopher Koch. PDF in `../../sources/arXiv/2605.20456-agentic-agile-v-vibe-to-verified.pdf`.

## Thesis
Agentic AI coding systems can plan, edit files, run tests, and open pull requests, but the evidence does not support the claim that autonomous code generation automatically improves engineering outcomes. The real bottleneck has shifted from prompt engineering to engineering process control: agents generate plausible artifacts faster than humans can inspect them. The paper proposes Agentic Agile-V, a process framework pairing an Agile-V lifecycle backbone with a task-level SCOPE-V loop (Specify, Constrain, Orchestrate, Prove, Evolve, Verify), so conversational intent becomes structured contracts and acceptance rests on evidence appropriate to risk.

## Key findings
- Productivity effects are context-dependent and contradictory: a Google RCT with 96 full-time engineers found ~21% less time on a complex enterprise task with AI, while the METR RCT found experienced open-source developers were 19% *slower* in mature repos despite expecting a speedup; a 2026 meta-analysis reports a statistically significant but moderate, highly heterogeneous effect (Sec. I–II).
- Agentic PR authoring is already at scale: the AIDev dataset reports 932,791 agent-authored pull requests across 116,211 repositories and 72,189 developers (Sec. I).
- Acceptance varies sharply by task: a task-stratified analysis of 7,156 PRs found documentation changes accepted more often than new features, with no single agent best across categories; a Claude Code PR study found high acceptance but substantial human revision, especially for bug fixes (Sec. II.C).
- Repository execution remains hard: GitTaskBench's best system (OpenHands + Claude 3.7) solved only 48.15% of tasks, with many failures from environment setup and dependency resolution (Sec. II.D).
- Context files cut both ways: AGENTS.md was associated with lower runtime and token use in one study, yet another found context files can reduce task success and raise cost when requirements are unnecessary or mismatched — motivating a minimal, decision-relevant-context principle (Sec. II.C, VII).
- Hardware is the cautionary case: RealBench reports low Verilog pass rates including 0% pass@1 on system-level tasks for evaluated models; "compilation is not proof" (Sec. II.E).

## Relevance to the book
This is exactly the peer-reviewed counterweight Chapter 3 needs to balance Ahuja's opinion writing on vibe coding vs spec-driven development. It reframes the vibe-vs-spec debate as "conversation discovers intent; structured artifacts control implementation; evidence controls acceptance," which maps directly onto the chapter's intent-driven-development (ICE) and AI-native-engineering threads. Its risk-adaptive acceptance gates (R0–R3) and SCOPE-V loop give the book a concrete, citeable process model rather than a single writer's stance, and its contradictory RCT numbers let the chapter show that neither hype nor dismissal survives contact with evidence.

## Stance
empirical-vibe / vibe-critical / pro-SDD — a synthesis paper that rejects both extremes ("not merely a toy... neither a universal productivity multiplier") using controlled trials and benchmarks, then argues for spec-driven, evidence-gated engineering ("verified engineering with agents inside the loop") over vibe coding at scale.
