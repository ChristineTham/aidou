# Mining Architectural Quality Under Agentic AI Adoption: A Causal Study of Java Repositories

> Source: arXiv:2606.13298 (2026-06-11). Oliver Aleksander Larsen and Mahyar T. Moghaddam (University of Southern Denmark). PDF in `research/arXiv/2606.13298-architectural-quality-agentic-causal.pdf`.

## Thesis
This is the first causal mining study of how agentic AI coding tools ("vibe coding") affect software *architecture*, as distinct from prior code-level work. Using a staggered difference-in-differences design over 151 Java repositories, the authors find that observable agentic AI adoption does not degrade architecture in established projects over a six-month window. The headline 6.7% decline in architectural smell density is shown to be a denominator (code-growth) artifact, not a real improvement — a cautionary methodological lesson about density-normalized metrics.

## Key findings
- Architectural smell density (ASD) falls 6.7% after agentic adoption (Borusyak ATT β = −0.070, p = 0.004), the *opposite* of the degradation predicted by code-level studies (p. 8, Table 1).
- Decomposition shows this is a composition effect: raw smell counts are essentially unchanged (+1.1%, p = 0.82) while lines of code grow +12.8% (p = 0.003) and package count grows +9.7% (p = 0.032) — new code carries lower smell density than the existing base (p. 9, Fig. 4).
- Only hub-like dependency density survives multiplicity correction (−5.0%, Holm p = 0.003); no smell type shows significant architectural degradation (p. 8).
- Tool-stratified estimates are all negative and never positive: Claude Code −5.1% (n=44, p=0.039), Copilot −4.0% (n=14, p=0.005), Cursor −13.5% (n=15, p<0.001); dose-response interaction non-significant (p=0.716) (p. 10).
- Detection is explicitly *agentic-only*: adoption is identified via config files (CLAUDE.md, .cursorrules, copilot-instructions.md, AGENTS.md) and Co-Authored-By trailers; inline autocomplete leaves no signal (p. 5).
- Robustness is broad but bounded: under worst-case attrition (Lee bounds [−9.9%, −2.3%]) the upper-bound CI includes zero (p=0.239), so the effect "cannot be distinguished from null" in the pessimistic case (p. 13).

## Relevance to the book
Chapter 3's vibe-coding-vs-SDD debate leans on Ahuja's opinion; this paper supplies peer-reviewed empirical counterweight (SEAA 2026 / Springer LNCS). It directly rebuts the strong "AI erodes architecture" claim for established Java projects over the short term, while also warning against the opposite over-claim ("AI improves architecture") — a nuance that models the careful reading the chapter should encourage. It contrasts usefully with the code-level He et al. finding (+30% warnings, +41% complexity), showing code-level and architecture-level effects diverge.

## Stance
empirical-vibe — a causal, DiD-based empirical study of real agentic AI adoption that neither cheerleads nor condemns vibe coding; it finds no short-term architectural degradation in mature Java repos, but insists on decomposition and longer windows before drawing conclusions.
