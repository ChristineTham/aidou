# Does Prompt Formatting Have Any Impact on LLM Performance?

> Source: arXiv:2411.10541 (15 Nov 2024). He, Rungta, Koleczek, Sekhon, Wang, Hasan. PDF in `research/arXiv/2411.10541-prompt-formatting-impact.pdf`.

## Thesis
Prompt *format* (the structural template wrapping otherwise-identical content) measurably changes LLM performance, contrary to the common assumption that it is stable across templates. The authors hold content constant and vary only structure/syntax across four human-readable formats — plain text, Markdown, YAML, and JSON — then evaluate OpenAI GPT-3.5 and GPT-4 models on six benchmarks spanning reasoning, code generation, and code/NL translation. They measure sensitivity (best-vs-worst gap via matched-pair t-tests), consistency (fraction of identical answers between format pairs), and transferability (IoU overlap of top formats across models).

## Key findings
- Format was compared across **four templates — plain text, Markdown, YAML, JSON** — with content, meaning, and the five prompt components (persona, instructions, examples, output-format, user ask) held constant (§2.2, Table 2, p.9).
- Models: **four GPT variants** — GPT-3.5-turbo-0613 (4k), GPT-3.5-turbo-16k-0613, GPT-4-32k-0613, and GPT-4-1106-preview (128k, "GPT-4-turbo") — run via Azure OpenAI (§2.3).
- Six benchmarks: **MMLU** and **NER Finance** (NL2NL); **HumanEval** and **FIND** (NL2Code); **CODEXGLUE** Java↔C# and **HumanEval-X** Java→Python (Code2Code) (§2.1).
- Headline swing: **GPT-3.5-turbo's performance varies by up to ~40% on a code (translation) task depending on template** (Abstract). Concretely, GPT-3.5-turbo-0613 HumanEval pass@1 goes from 40.24 (Plain text) to 59.76 (JSON) — a ~49% relative / ~20-point absolute jump (Table 4).
- Even larger swings appear per-benchmark: **FIND shows a "dramatic 200%" gain** switching Markdown→Plain text on GPT-3.5, and **HumanEval on GPT-4-32k-0613 boosts "over 300%"** switching JSON→Plain text (§3.2) — that last case: JSON 21.95 vs Plain text 76.22 pass@1 (Table 4), caused by the model emitting chain-of-thought but no code under JSON.
- All format sensitivities are statistically significant (matched-pair t-test p<0.05) **except GPT-4-1106-preview on HumanEval (p=0.055)** (Table 1).
- **Larger models are more robust.** Coefficient of Mean Deviation (CMD): GPT-4-1106-preview stays **below 0.036** across all benchmarks; GPT-4-32k-0613 **≤0.043**; GPT-3.5 series ranges **0.035–0.176** (Appendix D.2, Fig. 6). GPT-4 is also more *consistent*: GPT-3.5 MMLU consistency scores are below 0.5 (only **16% identical** answers between Markdown and JSON), while GPT-4 exceeds 0.5 (§4.2).
- **No universally optimal format.** Preferences are model-specific: GPT-3.5-turbo favors **JSON**, GPT-4 favors **Markdown** (§5.2, Table 3). Best format also varies by task — e.g. NER Finance is best in **Plain text** for GPT-3.5 but **YAML** for GPT-4; HumanEval-X favors **YAML/JSON**; MMLU favors **JSON** for GPT-3.5 but **Markdown** for GPT-4 (Table 1). Cross-series template transferability is low (IoU often <0.2), while same-sub-series models overlap highly (IoU >0.7) (§5.2). Sensitivity is a general trait, not tied to the skill/domain a task requires (Appendix D.1).

## Relevance to the book
This is the empirical backbone for Chapter 2 §2.4 "Everything Becomes Markdown": it demonstrates, with controlled experiments and statistics, that the *format* you feed an LLM — not just the wording — measurably shifts accuracy, sometimes by tens of points. It uniquely supplies the honest nuance the section needs: there is **no single universally best format**; the winner depends on model family, model size, and task (GPT-4 leans Markdown, GPT-3.5 leans JSON). It also supports the book's broader "structure matters, and newer/larger models are more forgiving" theme, since GPT-4-turbo is markedly more robust to format than GPT-3.5. Cite it to justify defaulting to Markdown for GPT-4-class models while cautioning readers not to assume any one format transfers across models.

## Stance
Supporting evidence (with caveats) — endorse the "format matters" claim; cite carefully because it argues *against* a single optimal format.
